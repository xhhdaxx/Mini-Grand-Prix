# Mini Grand Prix 赛道设计与导入规范

> 规范版本：1.0
> 生效日期：2026-08-10
> 适用范围：所有新设计、重画或导入的赛道

本文档是 Mini Grand Prix 新赛道的统一验收基线。关键词“必须”“不得”“至少”表示强制要求；“建议”表示允许根据参考图和驾驶体验调整。

上海提供主赛道和 P 房尺寸基准，拉斯维加斯提供独立曲线维修区参考，摩纳哥提供完整 `50 m → 限速区 → 50 m` 进出站参考。旧赛道中不符合本规范的历史几何不得作为新地图的复制模板。

## 1. 固定技术规格

| 项目 | 标准值 | 要求 |
|:---|:---:|:---|
| 世界比例 | `scale = 24` | 横纵必须相同，`worldScaleX/worldScaleY` 均为 `24` |
| 主赛道半宽 | `130` | 总路面宽度 `260`，即约 6.5 辆 40 px 赛车宽 |
| 路肩宽度 | `8` | 两侧均绘制红白路肩 |
| 单侧缓冲区 | `86.666…` | 默认 `halfWidth * 2 / 3` |
| 控制点采样 | 每段 `32` 点 | 由闭合 Catmull–Rom 样条生成 |
| 正赛圈数 | `3` | 排位赛和计时赛仍为一圈 |
| 同场车辆 | 玩家 + 6 辆 AI | 六个 AI 车队都必须能完赛和进站 |

控制点坐标是形状数据，乘以 `scale` 后才是世界坐标。不得通过修改道路宽度来修复相邻弯重叠；应移动或增加控制点。

## 2. 主赛道几何

每条赛道定义至少包含：

```js
trackId: {
  name: 'Circuit Name',
  laps: 3,
  raceDistanceMeters: 0000,
  scale: 24,
  width: 130,
  controls: [/* 闭合轮廓控制点 */]
}
```

强制要求：

1. 控制点按赛车行驶方向排列，样条首尾闭合且切线连续。
2. `raceDistanceMeters` 使用赛道公布的一圈实际米数，不使用像素弧长代替。
3. 每个弯必须保留完整 `260` 世界单位路面宽度，`roadScale` 默认为 `1`。
4. 非相邻路段不得发生路面、路肩或缓冲区重叠。
5. 需要明确分开的两段中心线距离必须大于：

```text
2 × (halfWidth + curbWidth + bufferWidth) + 120
= 2 × (130 + 8 + 86.666…) + 120
= 569.333… 世界单位
```

这会在两侧完整缓冲区之外至少留下 `120` 世界单位可见草地。紧凑弯组不能以中心线刚好不交叉作为验收标准。

6. 发夹、S 弯和回头弯应增加控制点细化曲率，不得用锐角折线或相互穿越的样条妥协。
7. 起终点附近必须给发车位、维修区分流和相机初始画面留下足够直线空间。

## 3. 主赛道路面与边界

渲染和碰撞统一使用 `track.samples`：

- 路面半宽：`130`。
- 路肩外沿：`138`。
- 缓冲区外沿：`224.666…`。
- 空气墙位于缓冲区最外沿，并扣除车辆碰撞半径。
- 路肩、浅灰缓冲区、砂石区分别按现有车辆规则减速。
- 小地图、结算分段图、AI 赛车线和最近点查询必须读取同一套采样数据。

不得为 Canvas、AI 和碰撞分别维护不同的赛道轮廓。

## 4. 维修区固定尺寸

新赛道必须使用上海规格：

| 项目 | 标准值 |
|:---|:---:|
| 维修区道路半宽 | `62` |
| 快速/工作通道中心偏移 | `29` |
| 单个车队 P 房长度 | `276` |
| 相邻车队 P 房中心弧长 | `360` |
| P 房横向停车容差 | `22` |
| 车队数量 | `6` |
| 停稳服务速度上限 | 内部值 `24` |
| 换胎停稳时间 | `2.5 s` |
| 安全释放检测距离 | `260` 世界单位 |

入口、主体和出口道路必须保持完整 `124` 总宽，不得在端头收成尖角。匝道端头应整体埋入主赛道路面，通过道路叠合实现连续接入。

## 5. 维修区分段与距离规则

完整路线按行驶方向必须是：

```text
主赛道
→ PIT IN 汇出段
→ 完全离开主赛道后的非限速段（至少 50 m）
→ 入口限速白线
→ 首个 P 房前 30 m
→ 六个 P 房
→ 最后 P 房后 30 m
→ 出口限速白线
→ 非限速 PIT OUT 段（至少 50 m）
→ 开始汇入主赛道
→ 完全回到主赛道
```

距离必须沿维修区中心线测量，并按以下比例换算：

```js
meters = routePixels * track.raceDistanceMeters / track.totalLength;
```

强制不变量：

- `entryEnd → entryK >= 50 m`：完全离开主赛道后至少 50 m 才出现入口限速线。
- `entryK → firstPitBox = 30 m`：入口白线位于首个 P 房前精确 30 m。
- `lastPitBox → exitK = 30 m`：出口白线位于最后 P 房后精确 30 m。
- `exitK → exitStart >= 50 m`：解除限速后至少 50 m 才开始汇流。
- 50 m 过渡段不得包含 P 房，不得提前触发或延迟解除 `pitSpeedLimited`。

`entryStart/entryEnd` 表示 PIT IN 汇出范围；`exitStart/exitEnd` 表示 PIT OUT 汇流范围。`entryGate*` 和 `exitGate*` 只能覆盖允许合法跨越主赛道边界的连接段。

## 6. 维修区路线函数

所有消费者必须使用 `getPitRoutePoint(track, k, lane)`：

- `fast`：靠主赛道的快速通道。
- `work`：靠 P 房的工作通道。

返回值必须包含连续且有限的 `x/y`、`tx/ty`、`nx/ny`、`k`、`idx` 和 `amount`。相邻采样不得跳变，入口和出口端点切线与主赛道点积必须接近 `1`。

可用两种实现：

- 法线平移：适合维修区与主直道大致平行的赛道。
- 三次贝塞尔：适合维修区跨越弯道或入口、出口航向不同的赛道。

无论采用哪种实现，渲染、玩家路面识别、AI 寻路、P 房坐标和限速白线必须共享该函数。

## 7. 维修区视觉

| 元素 | 标准 |
|:---|:---|
| 路面 | `#858792` |
| 外轮廓 | `#30323a` 黑色实线 |
| 快速/工作通道分隔线 | `#f5d76e` 黄色虚线 |
| 限速线 | 白色实线，宽 `5` |
| P 房 | 车队色填充 + 白色描边 |

连接段可选择：

- 上海样式：开放连接 gate、白色虚线、显示 `PIT IN/PIT OUT` 标牌。
- Monaco/Belgium/Abu Dhabi/Las Vegas/Baku/Jeddah 样式：黑色实线、隐藏文字标牌。

视觉差异不得改变合法过渡、限速、换胎和安全释放规则。

## 8. 比赛规则

1. 玩家必须按 `P` 请求进站；未请求时普通越界不得被视为合法 PIT IN。
2. 合法 PIT IN、两条限速线之间以及合法 PIT OUT 全程暂停赛道界限累计。
3. 两条白线之间自动限速，内部上限为 `115`；不追加维修区超速罚时。
4. 车辆只可在自己车队的完整 P 房范围内接受服务。
5. 完成服务后更换轮胎、轮胎温度设为 `72°C`、损伤降至原值 `35%`、ERS 恢复 `100%`。
6. 干地正赛必须实际完成至少一次换胎；同配方新胎有效。
7. 出口白线只解除限速，不恢复赛道界限；完全汇入主道后才清除 `_pitExitActive`。
8. 安全释放遇到高速来车时必须等待，放行后 HUD 引导切换为 `PIT OUT`。

## 9. 新地图接入清单

新增赛道时必须同步以下位置：

1. `src/game/track.js`：赛道定义、维修区配置、路线分支、P 房起始位置、合法 gate 侧别。
2. `src/game/track-meta.js`：国旗、地点、弯数、实际长度。
3. `src/game/ai.js`：独立维修区路线和适合该采样间距的前瞻值。
4. `src/renderer/track-render.js`：维修区视觉样式集合。
5. `src/utils/storage.js`：仅在赛道属于锦标赛时加入 `SEASON_TRACKS`。
6. `README.md`、`docs/prd.md` 和游戏内规则：同步赛道数量与名称。
7. `tests/run.js`：加入几何、维修区和六队 AI 回归。

建议按以下顺序实施：

```text
参考图取点
→ 主赛道闭合与净距测试
→ 维修区中心线和 gate
→ 六个 P 房
→ 30 m 限速线
→ 两端 50 m 非限速段
→ 玩家与 AI 接入
→ Canvas 冒烟测试
```

## 10. 最低自动化验收

每条新赛道至少测试：

1. ID、名称、弯数、`raceDistanceMeters`、24 倍比例和 130 半宽。
2. 首尾闭合、控制点数量、样条坐标有限。
3. 非相邻路段的路面、路肩和缓冲区净距。
4. 维修区相邻点连续、端点与主赛道同向、道路半宽恒为 62。
5. 六个 P 房唯一、长度 276、相邻中心弧长约 360。
6. 首/末 P 房到限速线分别精确 30 m。
7. `entryEnd → entryK` 和 `exitK → exitStart` 分别至少 50 m。
8. PIT IN/PIT OUT 只在正确侧和 gate 范围内合法。
9. 限速区、换胎、ERS 补满、安全释放和赛道界限状态正确。
10. 六支困难 AI 都能完成三圈、至少进站并换胎一次。

## 11. 浏览器验收

通过本地 HTTP 服务进入新赛道，至少确认：

- 菜单卡片和赛道元信息正确。
- 小地图与参考图方向、弯组和比例一致。
- 相邻弯之间能看到明确草地区，缓冲区不粘连。
- 起点、发车位、PIT IN、六个 P 房、两条白线和 PIT OUT 正常显示。
- 实际完成一次进站流程，入口 50 m 段不限速、白线后自动限速、出口白线后解除限速、50 m 后才汇流。
- 排位赛、正赛和单人计时均可启动，控制台无启动错误。

最终闸门：

```bash
node tests/run.js
git diff --check
```

两项均通过且浏览器冒烟测试无错误后，赛道才算符合导入规范。
